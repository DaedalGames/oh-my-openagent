### Changed

- `omo` now reaches the senpi engine only through its published package exports, never through files inside the engine's install, so a future engine release that stops shipping those files keeps working. A launch whose engine install is incomplete still gets the same reinstall hint.
- A stream event that the engine cannot serialize no longer crashes an `omo --mode rpc` session silently. With the next engine release, the client receives a failed `prompt` response with `errorCode: "invalid_stream_event"` and the cause, and the session exits with code 1. omo's earlier install-time patch of the engine never reached the bundled engine that omo actually launches.
